# 买方采购：保函模式罚则

适用于我方向上游采购、由卖方向我方承担违约责任的保函模式。craft、review及XQY共用本规则；Word技能只负责落实已定文字。下游我方供货另用[下游保函责任原则](downstream-guarantee-policy.md)，不得混用。

## 默认值与原合同的关系

**默认罚则金额F＝保函额度G－预付款数额P；原合同对同一违约事项已有明显更高、对我方更有利的罚则，保留原标准。** 先读原条款及其联动限制，再计算和比较，不为贴合模板、责任对等或保函覆盖而降标。

原文缺失或同口径低于默认值时，在本次已授权的罚则修订范围内采用默认值；用户对本单明确另定的条件优先。只读审核仅说明差异和处理建议，不借本规则改合同。该默认值用于本次处理的违约事项，不把迟延、拒交、转售、开票、保函核验等不同罚则全部改成一个固定金额。

## 计算与比较

1. **先对齐金额。** G、P取本单约定且对应同一交易或批次、币种和计算时点的金额，记录各自基数及来源。签约时尚未付款不等于约定预付款为零；后续抵扣、退款或减保不自动改变罚则，另有明确约定时从其约定。
2. **识别保函构成。** 合并保函包含预付款和履约额度时按其合计计算；拆为预付款保函与履约保函的，核对对应构成后计算G－P。不得只拿履约保函再减一次预付款，也不得把不同交易、不同期间或无关担保简单相加。计算默认值不证明各份保函可以互相挪用或银行已承保全部罚则，实际覆盖另按[保函实务](buyer-guarantee-practice.md)核验。
3. **比较实际保护。** 对同一违约事项展开原罚则的触发条件、基数、固定金额或费率、计日、累计上限及例外；再比较可得金额和适用范围。较高百分比乘较小基数未必更高；日罚、一次性罚款和不同触发条件不能只取数字最大值。日罚前期低于固定额、后期高于时，应分阶段说明，不能把较高累计上限说成任何天数都更高；保留既有计罚机制，不机械改成一次性罚款。不能明确比较的，保留原文，列明具体差异和缺少的条件，不先降到默认值。
4. **保留高标准的完整效果。** 原罚则明显更高时，金额、基数、计罚方式及有利适用范围一并保留；不能新增“以保函额度/差额为限”“仅由保函赔付”等文字间接压低，也不能套用下游不保留历史比例罚则的规则。已有较低总上限或交叉条款与高罚则冲突的，定位冲突并作最小处理，不自动把全部责任改成无限责任。

缺G、P或构成不明时保留公式并列缺项；差额为负先核对口径，不改成零掩盖问题。若确认仅有等额预付款保函、G＝P，差额如实为零，但不得因此删除已有罚则或认定卖方免责；另设正数罚则需本单确认。

## 罚则、退款与银行赔付

F是罚则的默认金额，**不是卖方总责任上限，也不是银行必赔金额**。退款本金、违约金、依法可赔偿损失及银行实际赔付分别核算，同一权益不重复受偿。原合同更高罚则超过保函实际覆盖时，保留卖方责任，并按M03核对未清偿差额的承担；不凭主合同文字扩大银行承保，也不为匹配保函而删掉卖方补差责任。

违约金调整风险依[民法典第585条](https://www.court.gov.cn/zixun/xiangqing/233181.html)及[合同编通则司法解释第64—65条](https://www.court.gov.cn/zixun/xiangqing/419382.html)结合损失证据核验（2026-11-26核对）。有具体风险时单列依据及影响，不仅因原标准高于模板就主动降低，也不承诺原约定必获全额支持。

## 虚构核对例

| 已知条件 | 处理 |
|---|---|
| 总价1000万元，约定保额350万元、预付款300万元；对应罚则尚缺 | 默认50万元，即合同总价5%；只在已授权范围内落笔 |
| 同上，原合同对该违约约定总价10%且无更低适用上限 | 保留100万元，不降为50万元；银行实际覆盖和卖方补差分别核对 |
| 同一交易明确拆为300万元预付款保函＋50万元履约保函，预付款300万元 | 默认350－300＝50万元，不算成50－300；两函可赔范围各自核对 |
| 原条款为受影响批次价款20%，批次200万元 | 结果40万元；不能只因20%高于5%就判为更高保护，先对齐违约事项及适用范围 |

交付时只解释本次实际差异。已保留且无待确认事项的高罚则不另加批注，内部公式和模板比较不塞进合同正文。
