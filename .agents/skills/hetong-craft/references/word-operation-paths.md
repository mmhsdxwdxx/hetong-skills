# Word 工具边界与替代路径

内容和写入范围先按 [授权边界](task-authorization.md) 确定；文档操作委派按 [共用规则](word-operation-agent.md) 执行。本文件不增加写入权限，也不扩展现有引擎的能力。

原生审阅颜色走[客户端显示检查](native-review-display.md)，不是OOXML正文格式操作；切换实现路径也不得用正文着色、底纹或改变作者来模拟审阅高亮。显示能力不足时沿用原生显示，不阻断其他已授权操作。

| 输入与交付 | 路径 |
|---|---|
| 只读理解已有修订/批注 | `word_reader.py` 重建多视图与线程，核对范围限制 |
| 无历史审阅冲突的普通清洁文本编辑 | `docx_tool.py`，另存、预演、验证 |
| 引擎支持的段落内真实修订/传统批注 | `hetong_redline.py inspect → plan → apply → verify` |
| 跨段、表格结构、目标与历史审阅重叠等引擎不支持项 | 记录具体拒绝原因，再选择支持该结构的本地 OOXML 实现或获准 Word/WPS 操作；无可靠路径则交付已完成部分和精确缺口 |
| 从已验证留痕底稿派生清洁版 | 先确定历史修订的取舍，再使用经过验证的接受修订/批注清理路径；现有红线引擎本身没有清洁导出子命令 |

替代路径必须先在副本或同结构虚构样本验证，记录确定的旧文、新文、锚点、作者及会受影响的 OOXML 部件。不得删保护、签名、宏或历史审阅来强行通过引擎；涉及这些结构且不能保持其语义时停止该项。用户授权修改带数字签名文件前须说明签名受影响，不能宣称修改后签名仍有效。

替代实现仍须证明：源文件不变；正文与授权目标一致；只拒绝本轮新增修订可恢复基线，只接受本轮新增修订可得到目标；历史修订/批注及相关扩展关系保留；未授权内容、样式、编号、媒体和域未改变。另做独立审阅结构审计和页面复核，不能以自建写入函数同时生成的期望值单独自证。

清洁副本须实际处理修订、批注与关联关系，而非切换“无标记”。将其正文、表格、页眉页脚等与按同一历史决策计算的留痕目标逐项比较；检查修订/批注残留和悬空关系，重新打开及渲染。保留原件与留痕底稿，不将未确认的历史变更静默接受。

`audit_docx_review.py` 只证明其检查范围内的结构，不证明法律、语义或 Word/WPS 兼容。目标客户端不可用时如实披露，不能仅因已生成 DOCX 就宣称客户端验收通过。
