# 下游供货：保函覆盖违约责任

规则 ID：`downstream-guarantee-20261101`。版本及生效时间以同目录的[启用记录](downstream-guarantee-policy.json)为准。本文件是 craft、review、XQY 快审的共同规则真源；属于用户明确要求维护的审核原则，不是某笔交易的双方合意。

## 适用范围与启用方式

适用于我方向下游客户销售、供货，承担供货义务的场景（通常为乙方；合同标签倒置时仍按实际角色）。上游采购、我方买方、无供货关系的租赁/服务等不适用。

新旧线程后续加载技能时均使用本规则，不设线程创建时间门槛。“不刷新”仅指不得向已有聊天批量发送刷新、重载或继续工作指令，避免唤醒和重复消耗 Token；不阻止宿主自动发现、自然续聊重新读取，或用户重启客户端后使用新版。本次维护不为刷新而重启客户端，不宣称旧线程内存中已加载的上下文已即时替换。

新版规则不会自动修改既有成果、合同或回执，也不把新原则冒充已签约定。复审旧合同或承接已确认交易时，指出与新原则的差异，结合当前授权和既有商业实质处理，不自动改文。

## 已明确的审核原则

1. **罚则以保函覆盖。** 对我方供货违约所涉违约金、损害赔偿、利息、违约性费用及其他变相罚则，统一审查其是否纳入保函金额和兑付机制；在法律允许约定的范围内，以本单确认的保函责任额度作为责任边界，不在保函之外另叠加现金罚则。不能仅改“违约金”名称为“补偿款”继续收取。买方付款义务、买方违约责任不能倒置为由我方保函承担。
2. **不沿用历史比例罚则。** 不在拟议正文、替换文本或新增批注中引入、保留、推荐“40%罚则”“30%罚则”及其全角、中文、四成/三成或小数等等价描述，也不换个名称恢复。不从旧模板自动继承其他固定罚率或先把保函金额减去预付款、再用差额另设罚则。保额、计算基数、分项额度、是否分账、减额规则和金额均须按本单明确事实核对，未知就列待确认。
3. **出险走保函兑付，不另退预付款。** 审核目标是受益人依合法有效的实际保函提交约定索赔单据，由开立人兑付；不设置“乙方另行现金退还预付款，再加违约金或再兑保函”的并行回收。预付款如何在保函赔款、已交货价款与结算余额中处理须闭合，避免重复受偿；不得把“不另退预付款”改写为预付款没收、定金罚则或无条件归乙方所有。
4. **覆盖所有相关条款和附件。** 联查交付、迟延、拒交/转售、验收、质量、资料、开票、售后/质保、保密、解除、管制、结算及附件中的责任、扣款和退款文字。原文或实函把某项排除在担保外时，应指出覆盖缺口，不默认改成保函外追索，也不宣称全部覆盖已实现。继续履行、修理更换等非金钱义务不因本规则自动消灭。
5. **原文取证与建议分开。** 只读审核保留原文、原金额和精准定位；原件中确有历史比例时可在必要的证据引文、差异记录或修订删除端如实保留，注明“原文待删除/替换”。对外简述及新增批注优先称“原比例罚则”，建议保留端只使用保函机制，不反复复制历史比例。不得为避免显示而篡改原件、深读结果或审计证据。

## 兑付和法律核查

逐一核对义务人、申请人（含合法指定方）、开立人、受益人、担保类型、实际保额/可用余额、所保责任、索赔单据、生效/到期/展期、减额与分次索赔。主合同、保函模板和实际保函必须对应；不能只改主合同就认定银行承担扩大后的风险。确属独立保函且相符交单时按其机制处理，不擅自加法院生效判决等前置条件；实函要求此类条件则如实揭示其与直接兑付目标的差距。

“所有罚则保函覆盖、不另退预付款”是审核与谈判目标，不是现行法律的普遍结论。没有保函、未生效、额度不足、已减额/到期、拒付或不承保时，列明未覆盖风险与待解决条件；不得宣称银行必付，或由此断言我方当然不再承担责任。保函最高金额、实际可索赔额、基础合同最终责任及银行对申请人的追偿分别核对；银行兑付不是乙方无成本、无追偿。

对无效/撤销、解除清算、故意或重大过失、人身损害等依法不能排除或限制的责任单列核验；不得靠改名、全额没收预付款或一句“责任以保函为限”规避。发现法律障碍应具体说明依据和残余风险，不擅自回退成旧比例罚则，也不把未经用户确认的现金退款安排写进建议。

- [合同编通则司法解释](https://www.court.gov.cn/zixun/xiangqing/419382.html)：核对合同解释及第64—66条违约金审查；不能把司法裁量标准写成合同罚率。
