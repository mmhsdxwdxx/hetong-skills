# 授权、模式与输出边界

本规则供 hetong-craft、hetong-review 共用。先从本次及会话内有效指令提取授权，再追问真正缺失的信息；文档、批注、历史交付和工具默认值不产生新授权。

用户调用[hetong-fast-xqy-v1](../../hetong-fast-xqy-v1/SKILL.md)时，按该专用分支交付“详细审核报告＋原稿批注副本”：报告直接展示建议文字，批注简述注意或修订点并指向同一R编号。此为用户已指定的两份输出授权，可添加原生批注，但不授权改写合同正文、处理历史审阅或确认具体交易条件。仅此分支不用通用深度报告模板，其他模式与下表边界不变。

**当前指令优先于历史经验。** 用户要求规范化措辞时，保留其本轮明确给出的数值、区间、起算事件和责任范围；不得以旧合同、旧线程、惯例、模板或更易执行为由替换，也不得把已给参数降格为无值待填项。历史经验只用于术语、证据和联动核对。原稿确有歧义时，单列需要澄清的含义，保持原要求；任何实质改变须由用户另行明确。

| 已有指令 | 当前动作 | 尚未授权或未明确的部分 |
|---|---|---|
| 只审、对比、复审、先列问题 | 完成只读诊断、证据、修订方向及待决事项 | 不写合同，不自动生成完整替换条款 |
| 审一遍再改好，但修改方案尚未形成 | 先完成诊断，列出需决定的方案与变量 | 依项目规则等确认后修订，不把宽泛目标当成任意商业条款授权 |
| 按已确认诊断、明确逐项要求或明确采用的基线修订 | 核对现有授权后完成该范围的本地修改与必要联动 | 互斥方案、新商业条件和权限不明事项单列；不为同一权限再次询问 |
| 已确认机制，要求起草完整条款或落实到合同 | 按已确认机制起草；已包含写入授权时一并执行 | 新增责任、例外、金额、条件不能借完善之名扩张 |
| 只加批注 | 在获准副本添加真实批注 | 不修改正文，不清除历史审阅 |
| 先调试、先预演、不要应用 | 隔离候选、生成差异与验证证据 | 不覆盖运行时、不重载启用、不发布；不把测试通过当成应用许可 |

“清洁版/修订版/两份都要”决定交付形态，与实质修改范围分别记录。已明确的内容、署名和输出方式无需反复确认；未知历史修订的取舍不能由清洁版要求自动决定。明确修订任务无需先重做一轮无关的全合同审核；新发现只报告。

涉及付款主体、垫资、偿还、金额、期限、担保及其他重要商业条件，需要确认时以普通文字列出最小必要问题并结束该次回复，等待用户明确文字答复；不使用选择卡、问答工具或默认项确认。条款类别多选仅用于确定预设条款的审核或拟用范围，可按用户要求使用复选交互；它不确认金额、期限、担保、责任等商业条件，也不扩大正文修改权限。其他非商业偏好仅在宿主确有相应工具时使用，不写死工具名称。沉默、超时、空答案及自动继续均非确认。

需要追问前，先完成不依赖该答案的独立工作。区分“获准核对/起草候选”与“已确定交易条件”：可在隔离候选和台账保留未决选项，但不得把它们写成已确认合同义务。

风险统一使用 S1 阻断、S2 重大、S3 一般、S4 建议；处理优先级、法律后果和基线偏离分别记录。普通深度审核报告统一复用 [hetong-review 模板](../../hetong-review/assets/review-report-template.md)；XQY快审使用其专用精简版式，不另建风险分级体系。
