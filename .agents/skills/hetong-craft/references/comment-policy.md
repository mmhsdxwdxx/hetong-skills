# 新增批注的触发标准

适用于甲乙方及其他合同视角。固定条款是核对依据，新增批注用于处理具体问题；命中条款本身不构成批注理由。先比较本次基线，再决定是否需要增删、修订或提出实质待核实事项。

用户已指定的[XQY双文件交付](../../hetong-fast-xqy-v1/references/paired-delivery.md)另包含“履约注意”类批注：原文无需改字，但确有具体履行动作、条件或证据需要提醒时，可作独立完整的简短注意批注；Word批注与详细意见显示同一R问题编号，意见仍须独立完整；文件及技术映射不外露。仅“已符合某固定条款”仍不足以产生批注；此例外不推广为普通审核的默认输出。

| 核对结果 | 正文处理 | 新增批注 |
|---|---|---|
| 命中已选固定条款，原文已有充分且等效的安排，无须改动 | 保留 | 不加；覆盖情况可留在内部核对表 |
| 仅措辞与范例不同，权利义务、条件和救济实质相同 | 保留；明确授权的润色另按其范围处理 | 不为套用范例或展示已审阅而加 |
| 命中已选条款，确有缺失、冲突或须新增、删除、修订之处 | 按已授权范围处理；未确认商业条件保留待确认 | 加，说明实际缺口和本次处理 |
| 合同自身存在数字、逻辑、引用、主体、法律或履行机制问题 | 按已授权范围修复；不能确定时提出具体待核实事项 | 加，不以未命中固定条款或未选某类别为由遗漏 |
| 错别字、漏字、多字、明显笔误 | 未明确禁止改文时按v2.0.2规则直接最小修订 | 加简短批注；邻近同类笔误可合并说明，定位应可核对 |
| 存在会影响判断或条款落实的事实缺口、未决事项 | 不编造事实或代填商业参数 | 在批注授权内写清需核实的具体事项 |

所有新增批注和会成为批注的修订理由先执行[Word审阅隐私铁律](../../hetong-word/references/review-privacy.md)：不转介另一份文件、不泄露内部材料名称及索引。仅借鉴hetong方法也适用。

## 先判问题，再生成批注

1. 反查全文、附件、例外及本次有效版本；已有其他条款解决的问题不再认定缺失。分类为“必要”也不意味着必须改写、必须批注。
2. 区分“只命中预设条款”和“实际需要处理”。前者不进入新增批注清单；不写“符合Bxx”“已覆盖”“建议继续保持”等无行动要求的批注。
3. 需要处理时按一个可理解的问题组织批注。相同根因的多处修改合并解释，列明联动位置；不同问题及确需不同处理的事项分别保留。不按条款命中数分配批注，也不设掩盖真实问题的数量上限。
4. 以修订前的本次基线决定是否需要说明。本轮确有修复的，修后保留简明“已修订”理由；不能因修后已合格而把必要的修改说明筛掉。进入本轮前已修好、当前无需改动的，不重复新增批注。
5. 处理结果不得超出授权。本次明确只读只在报告中列问题；明确只批注不改正文。一般审核中的明确错误及中英同步直接在副本批注并修订；其他实质方案按授权实施。金额、期限、担保等未确认条件仍用普通文字确认，不因收紧批注而代替用户决定。
6. 该标准只控制本轮新增批注，不授权删除、覆盖或解决既有批注和修订历史。无须改动时允许新增批注为零，不为生成红线文件制造编辑操作。

## 交付前复核

逐条检查新增批注：对应了哪处真实改动、问题或实质待核实事项？若唯一理由只是命中预设条款，取消这条本轮拟新增批注。再对照问题和修订清单，确认未漏记真实缺陷、错别字及必要的联动说明。批注措辞和锚定按[批注质量与锚定](../../hetong-word/references/comment-workflow.md)执行。

篇幅、同号对应、直接纠错、中英同步及两页简报的完整边界见[统一审阅输出规则](../../hetong-word/references/review-rules.md)。
