# 合同任务的按需协作

供 `hetong-craft`、`hetong-review` 共用。适用于支持子代理的宿主，不依赖特定产品、模型品牌或工具名称。用户已指定：hetong 子代理默认与主代理使用同一模型；该专用要求替代本系列旧的固定型号及备选型号规则，不修改其他任务或全局配置。

## 何时派发

- 范围明确的局部修订、少量检索和常规验证由主代理直接完成。能由现有脚本或工具并发完成的抽取、计算、测试，不逐项另建子代理。
- 当存在足够完整、可独立验收的工作包，且主代理同时有其他必要工作可推进、预期收益超过交接和复核成本时，使用原生子代理并行处理，无需逐次询问是否分工。通常先派发1—2个工作包，按实际需要增减，服从宿主并发上限；不把代理数量当作目标。
- 不按条款逐个建代理，不让多个代理重复完成整份审核；需要独立复核时另行说明复核范围。短任务、紧密依赖链及同一文件的连续写入保持串行。
- 宿主没有子代理，或暂时无法安全派发时，由主代理继续已授权工作；不得为委派另接外部模型服务、切换账号或创建用户侧新对话。

## 模型与运行参数

优先使用宿主的模型继承能力，不传模型覆盖值。只能显式指定时，使用已核实的当前主模型标识，不把别名猜成另一个型号。主模型发生切换后，新派发任务沿用新的主模型；旧子代理实际使用的模型不能据此声称已经切换。

推理强度与速度默认继承当前会话设置，用户对本任务另有明确要求时从其要求；不为提速擅自降档或改用其他模型。不能以同模型安全派发时，先由主代理完成必要工作；确需其他模型才说明差异并取得明确选择。不因缺少运行参数回显而虚构参数已验证。

模型相同不等于必须复制整段历史。优先传递精简工作包与必要原文；不省略立场、最新用户要求、源文件身份及权限。长日志、旧谈判记录和无关技能不随每个任务重复加载。

### Claude Code CLI 与桌面 Code 本地会话

本仓库提供原生 `hetong-worker` 子代理，定义见 [Claude 适配入口](../agents/claude-hetong-worker.md)，由 `.claude/agents/hetong-worker.md` 软链接发现。需要委派合同工作包时优先使用它；定义中显式 `model: inherit`，调用时不再传模型覆盖值，以免全局子代理默认模型或内置 Explore 等代理的固定型号改变本任务的同模型约定。若宿主报告强制模型覆盖或继承未生效，由主代理继续，不擅自修改全局模型配置。

该子代理预载 `hetong-craft`；深度审核时按模式再读取 `hetong-review`。子代理不继承完整父会话，仍须提供本节下述交接信息，尤其是最新用户要求、选中类别与写入权限。普通短任务不为使用适配器而强行拆分，原生代理不可用时由主代理完成。适配入口不设额外权限模式、工具放行或永久记忆。

受理界面、类别选择与商业确认均由主代理持有；在交接包中传递已验证的受理回执路径和范围。子代理不重开问卷，不在无原生交互能力时伪造已问或已提交，也不使用另一个浏览器窗口重复收集同一选择。

## 分工边界

| 工作包 | 可委派内容 | 主代理保留的工作 |
|---|---|---|
| 数字与时间链 | 提取、复算金额税率、付款节点、期限及担保覆盖；返回公式、输入、结果及原文位置 | 交易结构、资金假设、商业参数和最终风险判断 |
| 法源核验 | 针对明确法律问题查询正式来源、施行日期、适用前提和相反依据 | 事实认定、法律适用、定级和最终意见 |
| 附件与版本 | 独立核对规格、数量、条款对应及差异，列明未覆盖材料 | 跨合同优先级、冲突处理和联动结论 |
| Word 制作 | 内容及权限确定后，按[Word 操作委派](word-operation-agent.md)制作、验证和渲染 | 内容决定、准确旧文新文及批注、最终验收 |

派发前统一源文件和版本、我方立场、材料范围及已知事实。主代理完成必要的全文冷读与整体交易还原；子代理所需核验可同时推进，但不能以某个分工结果代替主代理对全文及跨条款关系的判断。独立冷读完成前，不用子代理的既有结论引导冷读。

子代理可以返回反例、冲突及建议，不能替用户确认金额、比例、期限、担保等商业条件。用户本轮明确要求优先于历史合同和其他线程经验；不把甲乙方条款互换适用，不以模板补造交易事实。只读授权不会因并行扩大为修订授权；公开检索只发送抽象法律或技术问题。

## 交接与回执

交接至少包含：任务问题、源文件绝对路径及SHA或可核实版本、阅读视图、我方立场、用户最新约束、允许操作、必要技能入口、独立输出位置及完成标准。无须重复生成已有清单。主代理统一对外R/Q/C编号，避免不同代理自行生成相同编号。

回执给出结论、原文位置及必要引文、公式或来源链接、实际执行的检查、相反证据与未验证项。区分文件事实、复算结果、推断及待核实；不要回传整份原始日志代替结论。主代理处理重复发现和矛盾，核对关键证据、商业联动及高风险结论；不能把“子代理完成”直接当作通过，也不机械重做全部工作。

## 执行约束

- 同一文件集合只有一个写入者。只读核验可并行，输出使用各自目录；共享Word/WPS界面及同一文件的预演、写入、验证、渲染不并发操作。子代理不嵌套委派。
- 主代理推进与子任务独立的必要工作，不重复执行已派发的同一工作包。收到用户纠正时及时同步受影响代理；过期结果不得合入新基线。
- 等待使用宿主可被完成、消息或用户输入唤醒的机制。回执不足时给原子任务补充准确范围；写入失败按原有基线和恢复流程处理，不反复新建代理盲试。
- 评价分工效果使用端到端耗时、漏检误报、返工及实际用量。区分请求数、输入、缓存输入和输出，排除复制历史及重复累计；没有同题对照，不报告提速、费用或额度节省比例。
