# 甲方采购：最小修订与参考表述

实际角色为买方时使用，`craft`、`review`、XQY共用。条款正文仍由[甲方分类库](buyer-consolidated-clauses.md)维护；本页说明如何适配，不增加类别、不替用户确认商业条件。期货在本页指先订购、后备货交付的实物采购，不指交易所期货交易。

## 先锁定事实，再借用文字

参考模板不是权威文本，也不是本单交易事实。按本次已确认条件和当前基线逐项核对：现货/期货、设备及数量、价税与费用、预付款及尾款、共管资金释放、保函种类与责任范围、交付/验收/开票时点、违约金及上限。原稿冲突列为待核实，不能由模板代定。

仅借用能准确表达本单机制的句式。模板中的主体、账户、币种、配置、数量、金额、比例、日期、宽限期、银行、交货地及争议机构均不得随文字带入。主合同、付款表、交付附件和保函样式分别交叉核对，模板自身的混写、笔误和旧条件不构成基线。

商业实质也包括程序条件，不能只检查数字没变。例如原稿只约定“验收合格后付款”，不得借模板增加“收到结算单证后”这一付款前提；原稿已有该前提时则保留。确需新增资料、确认或通知门槛的，明确列为新增建议等待确认，不能称作原文的“明确化”。

| 场景 | 适配重点 |
|---|---|
| 期货或尚需下单备货 | 依本单安排串联预付款、PO/PI、原厂SN、发货与物流凭证；M17的历史周数仍须本单确认，不能覆盖已经约定的交期。 |
| 现货、已在库或立即可交付 | 核实库存、所在仓库、可交付数量、合法处分权、已有SN及现场验收。不得套入“收预付款后再下单”、等待数周产生SN或生产交期。是否存在进口、预付款或保函依实际材料判断，不能因现货一概删除。 |
| 混合或分批状态不同 | 按批次区分已在库、在途、待生产；不能用一个期货流程覆盖现货批次，也不能仅凭合同标题确定全单状态。 |
| 无GPU或非八卡设备 | 不套Fieldiag/DCGM、nvbandwidth及八卡互联要求；按实际标的和原厂规范确定验收项目。 |

## 最少文字表达关键变化

沿用[修订粒度规则](revision-workflow.md)：先保留原合同结构、术语和能用的句子；只替换有问题的完整字段、短语或分句，新机制优先补一个完整句子。原文已表达同一保护目标时保留原文，不为贴近模板再写一遍；既不惯常整段重写，也不拆成连续单字插删。

例如仅把付款期限由5个工作日改为3个工作日，留痕选区是`5个工作日 → 3个工作日`；只删`5`插`3`过碎，连同付款条件及其他义务整段替换过宽。最小修改以完整语义字段为单位，不以字符数最少为准。

“先讨论/先给修改建议”只交对应文字成果；已明确修订授权时直接实施该范围。用户明确“不加其他内容”“暂不讨论”的事项不借条款库补入。未确认的付款、担保和期限单列，不能先写新条件再称“待确认”。

只要逐条修改建议时，用定位、具体问题和最小处理方向表达；原稿已清楚的金额或付款句不再展开成新段落。只有明确要求替换文字或已获准起草该机制时，才给相应完整片段；事实不全的机制先列缺口，不靠长篇重写补齐。

署名、批注、清洁稿和文件名沿用本次明确选择。要求去掉全部批注时，在另存稿中清除批注及回复、锚点和关系，保留修订；要求不新增批注时不顺带删历史。只要留痕稿就不另制清洁稿；要求名称仅留版本号时采用`合同名称_vN.docx`。不把某次署名或“无批注”扩成其他任务的默认值。成品重新提取核对，原件保持只读。

## 保函分开核对，不能只看合计比例

- **开立行和验真**：使用M01的6家国有大型商业银行、12家全国性股份制商业银行完整名单，含获相应开函授权的境内分支机构。正文不能只写“6＋12家”或“甲方认可的银行”。官方线上验真须对应实际开立行、函号和受益人；卖方截图或网址不等于查验通过。名单范围是采购要求，不证明名单内任一家都会接受该样式。
- **种类与承保**：预付款保函核对未抵扣/未退还预付款，履约保函核对本单约定的履约责任；份数、比例与额度分别确认。仅保预付款的交易，不把违约金、税务损失、质保或全部履约义务塞入该函。存在双保函也不能用“各份保函均担保全部义务”混写。
- **生效与付款**：分别列申请、开立、送达、验真、生效和付款条件。保函要求先付款才生效，而合同要求有效保函到位才付款时，先揭示循环，不用“已开立”掩盖未生效。分次预付逐笔对应，不套固定比例。
- **减额与退出**：逐份列减额依据、所需确认、办理主体、余额、到期和注销条件。仅预付款保函按交付抵扣减额时，不传导到履约保函；已确认履约保函不减额的，持续保留其约定额度。预付款返还责任消灭也不当然消灭未结清履约责任。
- **索赔与银行文本**：合同要求、附件样式和实际出具保函三层分别核对。见索即付不等于零单据、无限金额或无期限；不能把合同里的“无需证据”当成银行已接受。约定适用URDG 758时核对与实际保函的衔接，不从模板自动加入或删除。无实际保函时只说明应满足的要求和待核实项。

## PO、PI、SN和压测要形成对应关系

PO/PI用于核对下单及交易资料，SN用于逐台识别，物流凭证用于核对发运；三者不互相替代，也不单独证明所有权。M17处理期货过程，M06处理发货前逐台核对，M09处理随货交付。某一时点已经履行的义务不重复索要，仍须检查对应批次及后续变化。

GPU服务器按M08的四类项目落实，而非只写“压测合格”：硬件与诊断、主机/设备间带宽、实际卡数及拓扑的互联、合理模型部署测试。用户要求采用成熟四类写法时，须读取M08正文并保留Fieldiag/DCGM、nvbandwidth名称和各项合格判据，不能为精简改成“诊断测试、带宽测试”等泛称而丢失可验收内容。测试工具及版本须适配实际配置；原厂设计带宽不直接等于现场工具必达值，判定口径和未公布的阈值须在测试前明确。保留原有复测、换货及费用分配，不自行增加功耗、时长、性能数值。

收货/外观初检、性能验收、货权转移、风险转移、尾款和保函减额分别定位。已经约定压测合格才付尾款或减保时，未完成压测不得由收货单或沉默验收提前触发；但不能借模板擅改原本另行约定的货权或风险转移时点。

## 可按已确认机制借用的短句

下列文字只在对应机制已经确定且属于本次授权范围时使用，空项按本单填写。需要新增机制或改变起算事件的，先列建议，不能以“措辞优化”直接落笔。

| 用途 | 参考表述 |
|---|---|
| 分批验收付款 | 甲方在该批设备按约验收合格后【期限】内，支付该批合格设备对应的剩余价款；不合格或未交付设备不触发其对应尾款。原稿另有已确认的单证等付款前提时，保留该前提，不从其他范例新增。 |
| 逐台抵扣预付款 | 已付预付款按【本单抵扣规则】逐台抵扣；各批验收款仅为扣除对应预付款后的余额。 |
| 分批开票 | 乙方应于每批【已确认起算事件】后【期限】内，开具并交付与该批价款等额、内容与实际交易一致的合法有效增值税专用发票。 |
| 对应未履行部分退款 | 乙方应于【起算事件】起【期限】内退还对应未履行部分尚未抵扣的预付款；退款义务不以乙方取得第三方退款为前提。 |
| 单证对应 | 每批资料应与该批设备的品牌、型号、数量及SN逐台对应；变更已锁定设备须事前取得甲方书面同意。 |
| 通知与经办权限 | 履约通知以可证明到达为准。收货、验收人员按书面授权履职；合同变更仍须由双方有权人员书面确认。 |

开票起点须保留“验收后”或“该批尾款付清后”等本单选择；不得因M15范例或另一模板改变起点、税率及期限。价税、运输、保险、压测等费用是否包含，按已确认的费用范围写明，不能套“固定包干”来扩大卖方义务。

## 责任和不可抗力

预付款退款、违约金、损失赔偿及保函赔付分别核算，同一损失不重复受偿。“保交比例”先确认是保证交付的数量比例、未交货价款的罚则比例，还是责任上限；不能相互折算成同一承诺。“责任对等”按已确认的基数、费率、起点及上限对照，不自行选比例或把全部责任一律封顶。

M02/M20针对的是扩大免责：普通上游断供、资金困难、市场变化及政策因素不自动构成不可抗力。符合法定条件的事件仍按其实际影响依法处理，核对通知、证明、减损及迟延后发生的情形；不得把所有法定不可抗力一并删掉，也不能约定违法继续履行。

- [合同编通则司法解释](https://www.court.gov.cn/zixun/xiangqing/419382.html)：第1条核对合同解释，第65条核对违约金调整，不把合同价款的某一比例说成法定上限。
- [独立保函司法解释（2020年修正）](https://www.quanzhou.gov.cn/zfb/xxgk/zfxxgkzl/fgwj/sfjs/202110/t20211022_2638134.htm)：第1、3—8条核对单据、金额、生效及审单；合同承诺与实际独立保函分开。
- [中国银行业协会名单](https://china-cba.net/Index/show/catid/146/id/43806.html)：核对6家国有大型商业银行及12家股份制商业银行名称；实际开函资格、授权及产品验真渠道仍逐笔查证。
- [NVIDIA DCGM](https://docs.nvidia.com/datacenter/dcgm/latest/user-guide/dcgm-diagnostics.html)、[nvbandwidth](https://github.com/NVIDIA/nvbandwidth)：核对诊断和带宽测试工具用途，不据此编造某配置的验收阈值，也不把在线诊断当成原厂维修结论。
