# 合同履约时间轴规范

用于把付款、交付、担保及发票放在同一时间顺序中，发现条件倒置、期限冲突、资金占用和保障空窗。由craft维护唯一正文，review及快审按需引用。它是**履约事件时间轴**，与`word_reader.py`记录作者修订活动的时间线不同。

## 何时使用

- 用户要求时间轴，或付款、验收、退函、索赔、开票等跨条款关系仅靠文字不易看清时使用；单一日期、小范围文字修改不强制画图。
- 审核中作为诊断图；修订中复算本轮修改的连锁影响；批注中只写关键冲突、影响及处理状态。时间轴本身不授予正文修改权，也不因出现一个节点就新增一条批注。
- 完整图放报告、修订说明或获准的分析附件，不自动插入合同正文、不把大表塞进批注。批注可引用对应R/Q/C编号，但仍应独立说明关键事实，不能只写“见图”。

## 一、先确定事件与证据

先从本次原件、附件、真实保函及履约凭证建立事件底稿：**条款定位／版本 → 触发条件 → 主体和行为 → 起算点 → 期限及日历口径 → 金额及计算 → 证据状态 → 后续事件**。底稿不必全部挤入展示表。

1. 区分合同约定、凭证证实的实际履行、独立复算、假设情景、待确认事项。签前无付款凭证时，不能直接称“已付款”；应写“本情景完成付款后累计已付”。
2. 日期确定用绝对日期；只约定相对期限时用`T0＋约定期限`，同时定义T0。自然日、工作日、小时、月分别计算；工作日须核对适用地区日历和调休，未核定不输出貌似精确的日期。“三个月”不直接换成90日。
3. 多个条款冲突时并列来源和条件，不擅自选一个作为确定期限；必要时分成方案A/B。未定数量、价款和日期使用变量，不把示例或旧合同参数带入本次交易。
4. 一张表只讲一个一致情景。正常交付、解除退款及部分交付可分别成表；不能在正常交付之后直接接上“全部未交付退款”，造成同一资金重复占用或重复回收。
5. 纵向按时间先后排列，不按行距等比例表示天数。签署、保函开出／生效／减额／到期、付款、到货、验收、货权与风险转移、退款、索赔送达、退原件、开票按实际相关性选取，不机械全列。相同日期但先后关系不同的，用同日不同事件行说明条件。

## 二、固定表头与版式

采购方默认表头严格为：

| 日期 | 我方现金流及付款义务 | 交付与担保 | 发票（万元） |
|---|---|---|---|

**不加“时间轴分析”合并标题行，也不另加单位行占表头。** 表前或表下注明币种、全表金额单位、情景和T0；“万元”是全表金额的简写，不仅指发票栏。外币写明如“全表金额单位：万美元”；元或亿元更适合时，明确同步末栏括号，不能混用单位或暗含汇率。文件标题、报告小节标题不受此表头约定限制。

| 项目 | 默认规格 |
|---|---|
| 纸张／版心 | A4纵向；左右各25.4mm；表格净宽159.2mm，约16cm；上下边距默认20mm |
| 日期栏 | 固定22mm，居中；绝对日期的年份与月日分两行；数字等宽 |
| 我方现金流及付款义务 | 52mm，用于付款条件、当期金额、累计及占用状态 |
| 交付与担保 | 50mm，用于交付、验收、覆盖条件、减额、失效及索赔节点 |
| 发票 | 35.2mm，用于开票触发、期限、取得／抵扣状态及时间差 |
| 字号／行距 | 表头及正文10.5pt；正文行距1.45；沿用报告的中文字体体系 |
| 单元格 | 左右内边距2mm，上下1.8mm；正文顶端对齐；行高随最长单元格增长 |
| 要点 | 一个要点一个独立段落；段间1mm；长要点自然折行，不用分号挤成一段 |
| 视觉层级 | 浅灰蓝表头和细边框；重要金额、触发条件加粗；风险色仅辅助，不作为唯一信息 |
| 跨页 | 重复栏目表头；整行尽量不跨页；情景标题和说明与首行同页；超长行先拆事件／移长说明，不缩字硬塞 |

三栏正文的宽度按常见文字长度设置，日期栏固定。信息过长先精简、拆要点或移至表下注；确需调宽时，保持总宽159.2mm并记录差异，不让内容自动撑宽表格。卖方任务按真实现金方向调整首栏为“我方现金流及收款义务”，并显式说明；不能把应收写成应付。非买卖合同亦只保留实际适用事件，发票空白写明原因而非虚构。

## 三、四类资金状态不能混算

| 状态 | 展示口径 | 不可误读为 |
|---|---|---|
| 应付 | 本事件条件满足后的当期付款义务；注明条件是否已满足、是否到期 | 无条件立即付款；与累计已付再相加的另一笔支出 |
| 已付 | 有凭证的累计实际支出；情景演算明确写“情景累计已付” | 仅凭合同即认定现实付款；扣掉退款后的净支出 |
| 待退 | 退款条件成立、应退且尚未到账的本金；必要时注明已到期／未到期 | 任意预付款均可退；已收到退款；包含违约金的总索赔额 |
| 资金占用 | 明确对象及口径，如未抵扣预付款、开函保证金、设备／库存占用 | 可与已付直接相加；交付后当然归零；完整会计净资产或最终损失 |

正常情景未触发退款时，可以在表下注统一写“本情景未触发待退”，不必每行重复零。未获付款凭证写“实际已付待核”，不能填0。已退款、银行赔付、经营回款分别列实际到账，不冲掉“累计已付”的历史口径；需要净支出时另标“累计净现金支出”。

预付款抵扣是账面结算，不是新现金流。退款本金、违约金、赔偿、利息及银行赔付分账，同一本金回收不重复统计。保函面额不从资金占用中直接扣除；面额、生效余额、承保债务、索赔条件及实际到账各自核对。计算“保障差额”须说明比较对象，仅表示该口径的差额，不等于损失或确定可获赔款。

交付与担保栏保留与现金相关的条件：验收是否完成、何时抵扣、何时减保、保函是否覆盖未退本金／相应责任、原件是否需交回、索赔须何时送达银行。退原件不直接等于银行责任消灭，但可能影响相符交单。名义到期不直接等于索赔可用截止。

发票栏区分“应开、已取得、认证／抵扣条件具备、已实际抵扣”。到期不证明已开票，收到发票不证明已抵扣。`—`只表示该情景本节点无新增事项，不证明现实中不存在或禁止提前开票。关键时间差可在表后短表单列，但仅在承保范围也覆盖相关责任时才谈保障是否充分。

## 四、按交付载体稳定排版

### Markdown

使用原生四列表格，单元格内用`<br>`逐点换行；日期可写`年份<br>月.日`。不使用Unicode框线、空格、制表符或依赖中文等宽字体来凑列宽，不使用外链SVG、图片或依赖联网的图形库。

Markdown本身不能保证毫米列宽、分页或所有阅读器都支持HTML换行。默认先交付可独立阅读的`.md`；需要精确视觉／打印时同时提供**自包含HTML**，不能以只有HTML替代明确要求的Markdown。HTML的CSS全部内嵌，不引用字体、脚本、图片等外部资源，不把本地绝对路径当依赖。

复用[Markdown虚构示例](../assets/contract-timeline-example.md)及[自包含HTML模板](../assets/contract-timeline-template.html)，替换整套情景，不沿用其中商业参数。模板允许长文自动换行；窄屏横向滚动，不把四栏挤成错乱窄列。

### Word／打印稿

使用真正的Word表格，关闭AutoFit，表格布局设为fixed；总宽159.2mm，明确设置表格网格及每个单元格的宽度（22／52／50／35.2mm），不能只设一处宽度。正文顶端对齐，每个要点独立段落，首行重复为表头，不设固定行高。若工具使用twip：总宽约9026；四列约1247／2948／2835／1996，舍入尾差放末栏。

设A4页面和匹配页边距；若放入已有报告，应检查其版心而非越界改整篇页面。现有版式必须保留时，按可用宽度等比适配并说明，不改变合同其他页的格式。完整表通常置于分析附件；是否写入合同依本次授权。

## 五、交付前核验

- 从原件／凭证复查节点及条件；独立复算金额、抵扣、余额、日期与时间差。实际记录、正常情景和违约分支不混排；来源及未决项能回溯。
- 对照修订前后重算受影响节点，联查付款、交付、验收、保函和发票；图中修复不等于合同已修复。批注只围绕真实缺陷或本轮修订，遵循[批注规范](comment-workflow.md)。
- 检查四栏、单位、段落换行、总宽、长文本、分页及重复表头。HTML断网打开仍有全部内容；Markdown不依赖其他文件才能理解。
- Word交付按[Office流程](office-workflow.md)渲染并逐页检查；分别报告结构、渲染、Word／WPS实机的验证范围，不能互相替代。
