# 内容已确定后的 Word 操作委派

本规则由 `hetong-craft`、`hetong-review` 共用，只适用于内容已确定、
操作已获授权的 Word 文档工作。已有授权直接沿用，无需重复确认。
模型与按需分工统一执行[合同任务协作](agent-collaboration.md)：子代理默认继承主模型，不固定型号；其他任务不自动套用本规则。

## 职责边界

主 Agent 确定合同立场、事实与法律判断、商业条件、正文和批注的准确文字、修改范围及输出方式。
子代理负责把确定的内容制作或写入 Word：定位、生成、排版、真实修订、范围批注、结构自检、
渲染及必要的 WPS/Word 操作。操作所需的机械提取可随工作包委派；内容未定阶段的阅读解释、
审核和方案取舍不属于此委派。PPTX、XLSX 不自动套用本规则。

子代理不得润色已定文字、补齐未确认条件、扩大范围或自行解释冲突。遇到原文不匹配、重复命中、
不支持的结构或内容矛盾，返回具体位置和缺口，由主 Agent 判断；不得清除历史修订/批注来绕过限制。

## 原生子代理与默认参数

按[合同任务协作](agent-collaboration.md)继承当前主模型及会话运行设置。使用当前宿主支持的原生派发与等待机制；不因使用不同宿主改变合同内容、授权及验收标准。不支持子代理或无法同模型安全派发时，由主代理完成已授权操作，不额外启动外部模型服务。

同一文件的完整制作周期交给一个写入者；主代理有其他必要工作时同步推进，没有可并行工作的小修改直接处理。模型相同不要求复制完整会话，以精简工作包交接。

## 最小交接包

主 Agent 将已有定稿或操作计划连同以下信息交给子代理，无需另造重复模板：

- **基线与权限**：源文件绝对路径及 SHA-256（新建文档则为定稿路径/版本）、只读要求、
  输出路径、允许操作、修订/批注作者、历史标记保留规则、目标软件及所需交付形态。
- **确定内容**：每项操作的条款/段落/表格定位、准确旧文与新文、完整批注及目标选区；
  已定排版要求和应原样保留的占位符。子代理不得自行决定金额、期限、担保或其他商业条件。
- **执行与验收依据**：所需技能参考、工具路径、预演/验证命令或检查要求，说明哪些目标软件
  操作确有必要；只传任务所需材料，不附整段谈判历史。
- **原生审阅显示**：按[配色检查](native-review-display.md)传递目标客户端、已见历史颜色、设置作用域及限制；只能在能力范围内调整原生审阅显示，不增改正文或批注的字色、底纹等格式。

同一文件的预演、写入、自检及渲染交给一个 writer，不为每条修订创建子代理；同一文件及同一
WPS/Word 界面不得并发写入。子代理不再嵌套委派。输出另存，源件不改。

工具分工沿用 [普通 DOCX 操作](docx-workflow.md)、[红线与批注](docx-redline.md)、
[Word 深读](word-deep-read.md) 和 [Office 精修与预览](office-workflow.md)：
Python 做精确修改，LibreOffice 批量转换/渲染，WPS/Word 做必要的目标软件验证；不逐处启动 GUI。
如用户明确要求通过 WPS 操作，按其指定方式执行。保留已有预演、验证及只读约束，不因委派降低门槛。

## 回执与主 Agent 验收

子代理交回成品路径、输入/输出 SHA、操作完成清单、预演与自检结果、实际渲染/目标软件检查证据、
失败及未验证事项，并如实记录模型、思考强度和速度。仅关闭本次打开的文档及临时程序。

主 Agent 独立对照定稿和成品，核对正文、修订语义粒度、批注正文及选区、作者、历史标记保留、
源件不变和未授权改动；使用现有 `verify`、重新提取及 `audit_docx_review.py --before` 等适用检查。
最终视觉验收仍由主 Agent 负责；结构正确、LibreOffice 渲染成功和 Word/WPS 实际兼容分别说明，
不能以子代理自报完成代替验收。

配色回执区分已设置并验证、保留原生显示、未验证；原生配色能力不足不阻断已授权交付，不改用正文着色补齐效果。

纯操作错误可在副本中修复；内容或权限缺口交回主 Agent。需要重试时从只读基线和原定操作计划
重建，不把部分成品当成新基线；连续两次受控修复仍失败时收窄原因，不靠提高强度或跳过检查宣告通过。
