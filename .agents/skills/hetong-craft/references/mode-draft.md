# 模式：起草（Draft）

从零起草合同、补充协议、附件或条款。目标是一次成型、可直接进入评审的稿子，
而不是"先随便写写"。

## 流程

### 1. 受理：先把需求钉死

用 [起草受理单](../assets/draft-intake-template.md) 逐项收集。关键信息缺失
（当事人、标的、价款/计价方式、履行期限、验收、违约责任、争议解决）时，
用 `ask_user_question` 集中提问，不要带着空洞假设开写。允许用占位符
`【待定：×××】` 处理的仅限：主体证照信息、账号、日期、具体数值等待填项——
商业结构（谁对谁负责、怎么付款、违约怎么算）不得留空。

同时确认：
- 合同在既有合同族中的位置（层级、双方、税目税率、接口文件），项目规则
  是否已限定其定位与禁区；
- 适用法与管辖偏好；
- 以哪份既有文件为体例基准（同族合同优先），还是全新体例。

### 2. 结构选型

按交易复杂度选骨架。常设条款序列（可按需增删，但删除项要有理由）：

1. 首部：名称、编号、当事人全称＋统一社会信用代码＋地址＋法定代表人
2. 鉴于条款（交易背景与目的，不创设义务）
3. 定义与简称（首次出现定义，全文统一）
4. 标的/服务范围（写到可验收的颗粒度；排除项用"不包括"明列）
5. 合同价款与支付（金额大小写、含税/不含税、税率、发票类型与开具时点、
   付款节点与条件、账户）
6. 交付/履行（时间、地点、方式、风险转移、货权流转）
7. 验收（标准、程序、期限、异议、默示通过/僵局兜底）
8. 质保/服务等级（SLA 须量化：指标、保证值/努力值、测量方法、违约上限、
   免责情形）
9. 双方权利义务与陈述保证
10. 知识产权与许可
11. 保密
12. 违约责任（计算方式、上限、免责与减责）
13. 不可抗力
14. 合同解除与退出安排（解除条件、善后、已付款项与货物处理）
15. 通知与送达（地址、视为送达规则）
16. 争议解决（诉讼/仲裁二选一、管辖地——注意法定专属管辖不得约定排除）
17. 生效、份数、附件清单、未尽事宜
18. 签署页（盖章、法定代表人/授权代表、日期）

### 3. 撰写

- 逐条写作，每条只规定一类事项；义务条款四要素齐全：**义务人、行为、
  期限/标准、违反后果**。
- 金额同时写大写与小写；比例写清基数；期限写明起算点（"之日内"自何时
  起算）与是否工作日。
- 语言执行 [语言体例规范](style-zh-hetong.md)。
- 与既有合同族有接口的，对接条款（验收、变更、付款、责任传导）逐字核对
  既有文件的对应表述，保证啮合；项目规则禁止的关系/通道一律不得写入。
- 拿不准的商业点不虚构，列入待确认清单。

### 4. 自检

- 对照受理单：每一项需求都有着落；
- 对照 [审查总清单](checklist-review.md) 的条款维度：无缺口；
- 数字复算：金额大小写一致、节点比例合计 100%、税率口径正确；
- 术语一致性：全文同一概念同一词；定义项均被使用且无漏定义；
- 交叉引用：条号、附件编号、合同编号指向真实存在的位置。

### 5. 交付

- 默认先交 **Markdown 评审稿**（便于逐条讨论），附待确认事项清单；
- 用户确认后如需 docx：按 [docx-workflow](docx-workflow.md) 的
  "新文档生成"路径转换；若同族有版式基准文件，以其体例为准；
- 任何 DOCX/PPTX 交付前按 [Office 精修与无头预览](office-workflow.md) 做批量渲染
  和视觉验收；PPTX 现有精修工具面向既有稿，不负责从零设计新演示文稿，需新建演示时
  先使用演示模板/专用工具生成，再进入精修与验收；
- 交付说明：结构取舍理由、待确认事项、建议的下一步（谁审、审什么）。

## 红线

- 不虚构事实：资质、授权、既往业绩、对方承诺，未经用户提供不得写入陈述保证。
- 不起草项目规则已否决的结构（如被禁的签约关系、资金通道）。
- 税率/税目表述必须与交易定性一致；拿不准就标注"【待税务确认】"，不编造文号。
- 管辖约定先查法定专属管辖（如建设工程施工由工程所在地管辖），约定无效比不约定更糟。
