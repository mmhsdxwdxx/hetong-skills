# 模式：审核（Review）

本文件是 `hetong-craft` 的审核模式路由与权限边界。深度审核、版本对比和修订后
关闭核验由同级专项技能 `hetong-review` 统一承接，避免在本文件再维护一套扫描、
分级和报告规则。

## 执行入口

先读取并执行 [hetong-review](../../hetong-review/SKILL.md)，按其要求加载
[审查总清单](checklist-review.md)、[风险模式库](risk-patterns.md)、
[语言体例](style-zh-hetong.md) 及 docx 工作流。专项技能是本模式的下游实现；
项目规则与 `hetong-craft` 铁律仍居上位。

## 权限与模式衔接

1. **审核、版本对比、复审默认只读。** 诊断报告可以给出风险、依据、修订方向和
   保护机制需求，但不直接改写合同原件。
2. **混合意图先诊断。** 用户同时要求“审核并补充/修改”时，先交付诊断，确认处理
   范围、商业方案、变量和输出方式后再继续。
3. **确认后的条款提案按完善模式。** 读取 [mode-improve](mode-improve.md) 的提案与
   商业决策纪律；只输出独立条款建议不等于原件已经修订。
4. **实际写入另走修订/完善。** 明确修改既有条款用修订，经确认补缺口用完善；
   执行基线确认、备份、dry-run、verify、重新 extract、变更日志和关闭核验。
5. **审核命令只读。** 审核阶段 docx 只用 `extract` / `search` / `verify`，不使用
   `replace` / `batch` 或其他写入子命令；用文件指纹和前后校验证明原件未变。

## 统一口径

- 风险词表沿用 **阻断 / 重大 / 一般 / 建议**；专项技能可用 S1–S4 作同级别简称。
  法律后果（无效、可撤销、不成为合同内容、补缺等）另列，不作机械一一映射。
- 发现以 R-ID 追踪，用户决策以 Q-ID 追踪；发现、裁定和实施分离，跨轮不重编。
- 报告必须有原文或缺口、条款/段落定位、数字底稿、法律核验、覆盖声明、反方复核
  和残余风险。重大发现用第二路径验证，未核实不得装确定。
- 完整保护条款不是“写得越狠越好”，须通过我方立场、对方可接受性和可执行性检查。

若专项技能缺失，先明确报告依赖异常，再按项目 `AGENTS.md`、上述资源和同等只读、
复算、法条核验、可追溯纪律完成力所能及的工作；不得静默降低覆盖与验证标准。
