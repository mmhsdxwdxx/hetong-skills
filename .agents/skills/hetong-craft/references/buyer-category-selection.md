# 甲方条款类别选择与整合使用

适用于我方作为购买方向上游采购服务器的审核、批注或修订。乙方立场不使用本流程。当前条款库由用户修订的24项来源整合为20项，保留全部A编号映射；只在同一类别内合并。正文真源按类别存于`clauses/buyer/`，[条款目录](buyer-clause-catalog.json)只保存派生索引，[分类入口](buyer-consolidated-clauses.md)供查阅。实际任务先选择类别，再按索引读取所选Markdown正文。

## 一次选择多个类别

1. 先核对本次指令和当前任务中已有的选择。用户已明确列出类别、明确要求全部类别或明确不用预设条款时，直接沿用；同一任务不反复提问。不把“必要条款”当成无条件必选，也不从“保护甲方”推断全部勾选。
2. 未明确时直接调用受理工具；它自动读取当前类别、条数及目录指纹，不需要先另行加载目录或导入内部函数。当前为保交条款、必要条款、一般条款、其他条款、共管条款；选项随目录变化。`buyer_clause_select.py list`仅作为维护和排错的公开命令，不是受理的前置步骤。
3. 按[受理工具与宿主交互](host-intake.md)调用实际组件：PiDeck用`hetong_buyer_categories`或`hetong_intake`；Claude主代理用`plan --host claude`输出的原生`AskUserQuestion`参数。前置单选按用户指定顺序为A保交付＋不资金共管、B不保交付＋不资金共管、C保交付＋资金共管、D不保交付＋资金共管；随后复选必要、一般、其他三类，附互斥的“其余类别均不选”。
4. 两题完整提交且核心校验成功后才形成完整类别回执。B＋“其余类别均不选”表示本次不用预设库；其他组合保留前题所选类别。任一题缺失、关闭、超时均不能当作空选或默认选择。
5. 无原生能力时说明缺口，按宿主后备规则处理；网页结果不计为Claude原生验收。不得将Markdown方框、普通选项数组或自由文本问答冒充原生复选。

前置题仅决定条款库范围；“不保交付/不资金共管”不表示同意具体商业安排、删除合同已有保障或豁免一般风险核验。具体条件仍按本单文字确认。

类别选择尚未答复时，继续文件锁定、全文阅读、客观复算和依法应做的风险检查；不自动追加或删除预设条款。显式提交空集合表示不调用本预设库，未提交或无回答则仍为待选择。

## 范围与授权分开

- 选择类别决定哪些预设要求参与对照，以及已获修订授权时哪些范例可用于适配；不是对每条范例的商业承诺、签约确认或正文写入授权。
- 未选类别不自动补入、不自动批改，也不代表原合同中该类别的条款应删除或用户接受其风险。合同已有文字中的违法、数字错误、内部矛盾和明确用户问题仍需报告，说明属于一般风险核验，不借此暗中套入未选模板。
- 类别之间有关联时仅提示依赖和影响，不自动勾选关联类别。例如仅选共管条款，可提示其依赖保函条件，但不得自动加入全部必要条款。
- 具体付款、金额、期限、担保、违约责任或取舍仍按[授权边界](../references/task-authorization.md)用普通文字确认，不用复选框批准商业条件。
- 记录本次选择、明确答复的来源和目录指纹；切换新合同或目录分类发生实质变化时核对范围。不要将一次选择写成所有以后合同的默认值。

## 生成选中条款

真实任务先从已验证的受理回执导出：`python3 scripts/hetong_intake.py export 产出/受理回执.json --out 产出/选中甲方条款.md`。这样同时检查源文件、目录指纹和明确选择。

以下原始生成命令用于维护或转换已有明确选择，不替代受理回执；输出必须放在实际任务的产出目录。`select`没有隐含的“全选”默认值，输出也不证明用户已确认。

```bash
python3 scripts/buyer_clause_select.py list
python3 scripts/buyer_clause_select.py select --category 保交条款 --category 必要条款 --out 产出/选中甲方条款.md --selection-json 产出/条款选择.json
python3 scripts/buyer_clause_select.py select --none --out 产出/不调用预设条款.md
```

明确要求全部时才用 `--all`。未知类别或目录异常应报错，不回退到全选。后续只读取选中条款正文；需要核对来源时用A编号映射，不能把映射表中的全部条目重新纳入执行范围。

## 合并与执行

- M01合并A01+A07；M03合并A03+A09；M06合并A06+A21+A22，其中A22作为独立子要求保留。A08、A14、A20等保留独立入口；相关不等于重复。
- M02/A02是其他条款的删除指引，M20/A24是一般条款的删除指引。只删除被识别为不利的自动免责、自动顺延或单方解除约定，不把“无范例条款”写入合同，也不恢复已被用户删除的旧范例。删除范围必须定位并服从当次授权；合法合规要求、通知减损、退款追偿等内容不能仅因出现政策或BIS字样而删掉。
- 跨类别同主题分别保留，某一类别单独选用时仍应可理解。两个已选指引命中同一处时，只执行一次并记录两个来源编号；不跨类别合并导致另一类别被隐含启用。
- 在同一条款内做重复语句整合，不丢失独立触发、期限、基数、例外或救济，不将3工作日、14日、7—10工作日、4—7周等不同口径合成一个期限。
- 报告或改动清单记录类别、M整合编号及A来源编号；对外合同和批注仍按原授权，不自动加入内部类别名或编号。
