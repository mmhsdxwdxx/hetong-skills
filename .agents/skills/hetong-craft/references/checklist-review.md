# 审查总清单

审核模式的扫描基准，完善模式的缺口对照表。分三部分：条款维度（有什么）、
风险维度（写得对不对）、多合同结构专节（合同族专项检查）。

使用时按审核范围裁剪：单份简单合同不必过结构专节；合同族审核三部分全过。

## 第一部分 · 条款维度（完整性）

| # | 条款 | 必查点 |
|---|---|---|
| 1 | 当事人 | 全称与证照一致、统一社会信用代码、地址、法定代表人/授权代表、签约权限 |
| 2 | 鉴于条款 | 只述背景不创设义务；与正文承诺不矛盾 |
| 3 | 定义与简称 | 首次出现即定义；全文使用一致；无"定义了不用、用了不定义" |
| 4 | 标的/范围 | 颗粒度可验收；排除项明列；数量、规格、质量标准确定或可确定 |
| 5 | 价款 | 大小写一致；含税/不含税明确；税率与交易定性匹配；计价依据可复核 |
| 6 | 支付 | 节点、条件、比例（合计 100%）、期限起算点、账户、逾期后果 |
| 7 | 发票 | 类型（专票/普票）、税率、开具时点（先票后款/先款后票）、票面内容与交易一致 |
| 8 | 交付/履行 | 时间、地点、方式、单据；风险转移时点唯一且明确；货权流转路径 |
| 9 | 验收 | 标准（量化）、程序、期限、异议期、不验收/僵局的兜底、默示通过条款 |
| 10 | 质保/SLA | 期间与起算点、范围与排除项、响应/恢复时限（量化）、违约计算、上限 |
| 11 | 陈述保证 | 双方主体资格、授权、不侵权、合规；无虚构建构（写进去就要担责） |
| 12 | 知识产权 | 背景/前景 IP 归属、许可范围、侵权处理 |
| 13 | 保密 | 范围、期限、例外（依法披露等）、违约后果、返还/销毁 |
| 14 | 违约责任 | 每种主要义务有对应后果；违约金计算基数明确；过高/过低调整机制；损失范围（含不含间接损失/可得利益） |
| 15 | 责任限制 | 上限存在且例外合理（故意/重大过失/人身不得限）；双方是否对等 |
| 16 | 不可抗力 | 定义、通知期限、后果（减责/解除）、持续性障碍处理 |
| 17 | 解除与退出 | 解除条件、程序、善后（已付款、已交货、保密存续）、违约责任存续 |
| 18 | 通知送达 | 地址/邮箱/联系人、视为送达规则、变更通知义务 |
| 19 | 争议解决 | 诉讼或仲裁**二选一**（约定两个机构＝或诉或仲条款无效风险）；管辖地合法有效（查专属管辖） |
| 20 | 生效与其他 | 生效条件、份数、附件清单与效力顺位、未尽事宜、语言版本 |
| 21 | 签署页 | 盖章主体与合同当事人一致、签署人身份、日期 |
| 22 | 附件 | 每份附件真实存在且有内容；正文引用编号与附件编号一致 |

## 第二部分 · 风险维度（正确性）

按风险模式逐条过，详见 [风险模式库](risk-patterns.md)。此处列最高频十条：

1. **定性错位**：合同名称/术语与实际权利义务不符（名为买卖实为代理等）
   ——税务与法律责任按实质认定，文字包装无效且有害。
2. **票实不符**：发票品目/型号与实交付不一致——刑事级红线，绝无例外。
3. **背靠背断链**：对客承诺的责任，上游合同未全额接住（期限更短、范围
   更窄、上限更低、免责更宽都是断点）。
4. **付款条件悬空**：付款依赖第三方行为（"收到业主款后付"）且无兜底
   到期日——注意《保障中小企业款项支付条例》对大型企业→中小企业的
   第三方付款条件禁令。
5. **验收僵局**：只有"验收合格付款"，没有对方不验收时的到期兜底。
6. **责任上限漏洞**：上限之下无例外，或例外条款被兜底条款吞掉。
7. **管辖无效**：约定管辖违反专属管辖（建设工程→工程所在地等）或
   与争议无实际联系（部分情形），等于没约定。
8. **术语分裂**：同一概念全文多种叫法；或同一词语指不同事物。
9. **附件空心**：正文全指着附件，附件只有标题。
10. **示例数字残留**：模板/测算稿中的示例金额被当成合同金额。

## 第三部分 · 多合同结构专节（合同族专项）

适用于两层/多层总分包、平行合同、框架协议+订单、三方程序文件等结构。

### 3.1 三流一致

- **合同流**：签约关系图与实际谈判/履行主体一致；不存在"影子合同方"
  （实际履行却无合同约束）或"挂名合同方"（只签约不履行）。
- **资金流**：付款路径与合同流一致；无合同关系的主体之间不得直接付款；
  "代收代付"安排必须有真实授权且不改变债权债务归属。
- **发票流**：开票关系与合同流一致；无合同关系不得开票；品目税率与
  各自身份的交易定性一致。

### 3.2 术语隔离（资质与定性防火墙）

- 无特定资质的主体（如无建筑业资质的总包），其对外合同的**措辞不得
  出现**需资质行业的定性词（工程、施工、竣工验收等）；实际作业由持证
  主体按另一层合同完成；
- 反过来：持证主体的作业合同不得溢到无资质主体的对客合同里；
- 检查方法：`search` 各定性词在每一份文件中的出现位置，逐处判定该层
  合同该不该出现该词。

### 3.3 税率匹配

- 每份合同的税目税率与其交易定性一致（货物 13%/现代服务 6%/建筑 9%/
  简易计税等，以签约时有效规定为准）；
- 同一合同涉及两个税率的，定价与开票方式是否符合"主要业务定率"等
  现行规则；设备+安装类是否符合现行一并按货物的规定；
- 低价货物+高价服务的拆分型合同：检查各项定价有无独立公允依据，
  防止被认定转移定价避税。

### 3.4 责任传导（背靠背）

- 对客合同的每项责任（交付、性能、SLA、质保、赔偿），在上游合同中
  有对应接住方；逐项列表比对：范围、期限、上限、免责、违约金口径；
- 质保金/保修期：上游承担不短于对客承诺；
- 追偿机制：对客赔付后向上游追偿的程序与时限。

### 3.5 三方/程序文件的纯度

- 程序性文件（责任边界、准入、联合验收、变更规则）只定程序，**不创设
  非签约对之间的给付义务**（下单、计价、结算、付款）；
- 非合同方之间的直接接触白名单化（安全、原厂核验、监管），且须同步
  合同相对方；
- 变更指令的登记与批准路径唯一，无"口头变更即生效"漏洞。

### 3.6 合同族联动修订检查

族内任一文件修订后：术语、条号引用、验收标准、变更规则衔接、付款条件、
附件版本在全部相关文件中重新比对一遍；修订记录注明联动文件清单。
