# 修订后关闭核验与复审

用于用户要求“复查是否改好”“关闭上轮风险”“定稿前复审”或审核自己参与修改的版本。
这是诊断类只读流程，不因为已经有修订说明就减少验证。

## 一、输入与独立性

至少识别：冻结原版、原审核报告及 R-ID、用户拍板与修订任务书、修订版、修订说明/变更日志、关联文件和各版本 SHA256。缺少任何一项时披露对关闭结论的限制。

先以原版、原报告和修订版独立核对，再用修订说明检查其自述是否真实。不要先被“已全部修复”“共改 N 项”等说明锚定。审核自己参与修改的版本时，也按他人作品重新取证，不沿用当时的自我判断。

## 二、逐项关闭，不以“已修改”代替“已修复”

每个原 R-ID 必须且只能有一个主状态：

| 状态 | 判据 |
|---|---|
| 已修复 | 修订文本、联动条款和验证证据全部满足关闭标准 |
| 部分修复 | 仅部分子问题或部分关联文件解决，剩余部分明确挂接 |
| 未修复 | 未改、改错、仅改说明、仍可在同一失败场景得到原不利结果 |
| 接受残余风险 | 有权用户在知情后明确接受；记录范围、理由和残余后果，法律底线不得以此放行 |
| 不再适用 | 交易、条款或文件结构变化使原发现失去对象，须证明而非当作忽略理由 |

关闭证据至少包括一项可复核结果，并与原风险性质匹配：

- 修订后文件＋条款名称/编号＋P/T 提取定位（如适用）＋逐字引文；行号只作辅助，若提供须由最终冻结文本工具生成并回查，不手填猜算；
- 独立复算公式、输入和结果；
- 原失败场景重跑后出现唯一、可执行的出口；
- 关联合同/附件同步位置及优先级检查；
- 法律命题在审核基准日的正式文本核验；
- 被删除机制的残留检索和交叉引用检查。

“正文有改动”“修订说明声称完成”“字数/条款数减少”均不是充分关闭证据。

## 三、全量 diff 与说明文档诚实性

1. 逐项比较原版和修订版，每个差异应对应已授权指令、已确认代笔决定或明确登记的机械修正。
2. 发现计划外实质改动时，不单列“已修复”就结束；新建 R-ID，评价其商业和法律影响并停止自动放行。
3. 建立“修订说明声称 → 正文实际落点 → 验证结果”表。说改了必须真改，说删了不得仍有残留；说明不实作为新发现，不粉饰计数。
4. 同根因多位置修改只保留一个主 R-ID，但所有落点和联动文件必须齐全，不重复计算风险或关闭数。
5. 编号跨轮稳定，沿用原 R-ID；新发现分配新 ID，合并/拆分保留映射，不为让台账好看而重编。

## 四、复审场景与数字

- 重跑原失败场景：对方不验收、不付款、不配合、反复修复、第三方索赔、解除返还等。
- 复算原错误及受改动联动的所有数字，不只检查被改的那一处；包括总额、税额、比例、期限、责任上限、担保余额和结算顺序。
- 检查新文本是否引入定义冲突、交叉引用错误、双重责任、责任上限例外反噬、附件残留或争议机制冲突。
- 检查改写是否只做了文风处理却改变数字、期限、义务分配、条件结构或引用关系；文风轮不得造成语义漂移。

## 五、完成与放行

纯诊断的完成不等于合同无风险；关闭核验的放行也不等于绝对无风险。建议同时满足：

1. 所有原 R-ID 均有五分类状态和证据，无“未看但视为关闭”；
2. S1/S2 已修复，或由有权用户明确记录残余风险接受/升级决定；法律强制底线不得靠接受放行；
3. 修订区和联动区没有未解释的 S1/S2 新发现，S3/S4 已登记；
4. 全量 diff 无未授权实质改动，说明文档与正文一致；
5. 数字、法律、覆盖、引用、附件和只读门禁通过；
6. 定稿文本没有过程标记、审核批注或任务状态残留，但合法签署空位和经确认保留的待填项不被误删；
7. 记录最终版本 SHA256。定稿后的任何修改另开复审轮次，不覆盖旧结论。

不满足时明确写“暂不建议放行”及最小待办，不为了完成轮次而降低等级或删除发现。
