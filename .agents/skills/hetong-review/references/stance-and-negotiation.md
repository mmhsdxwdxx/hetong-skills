# 我方立场、单方权利与谈判工程

用于把“中立的问题清单”转化为“保护我方且可谈成的审核结论”。在法律有效之外，识别商业不利、执行不利和锁定效应。

## 一、先确定多重角色，而不是只看甲乙称谓

同一主体可能同时是付款方与交付方、数据提供方与处理方、许可方与被许可方。按每项条款标出实际角色：

| 条款场景 | 我方角色 A | 我方角色 B | 审核含义 |
|---|---|---|---|
| 交付/验收 | 交付方：避免验收僵局 | 接收方：保留质量救济 | 同一“视为验收”条款的保护方向不同 |
| 付款/发票 | 收款方：现金流与到期确定性 | 付款方：先决条件、凭证与抗辩 | 不机械追求先票后款或先款后票 |
| 知识产权 | 权利方：保留背景成果 | 使用方：取得可用、可持续的许可 | 权属与使用权必须同时审查 |
| 数据 | 提供方：目的和合规边界 | 接收/处理方：权限、安全和事件责任 | 先识别法定角色，再分配合同义务 |
| 责任/解除 | 承担方：上限、程序与例外 | 请求方：核心风险救济和退出 | 不对全部条款统一追求“更强” |

如文本角色与真实履行不一致，先确认商业实质。用户未明确我方时，不输出假装立场的结论；可做中性检查或明确的分角色条件分析。

## 二、单方权利失衡扫描

逐条寻找“单方决定、最终解释、自行认定、随时调整、无需通知、无条件、全部、唯一、放弃”等措辞，但不能只凭词语定性。检查其对象、条件、证据和后果：

1. **价格与费用**：单方调价、新增收费、税率变化、成本转嫁、最低消费、自动续费。
2. **范围与质量**：单方改变需求、技术标准、验收规则、服务指标、交付物或排除范围。
3. **验收与结算**：单方认定合格/不合格、单方对账、单方扣款、最终用户或内部审批无限控制。
4. **履约控制**：单方暂停、要求更换人员、审计、进入系统/场地、调用数据、指定分包方。
5. **责任与抵扣**：单方确定损失、直接从应付款抵扣、扩大赔偿、免除自身责任、限制对方救济。
6. **期限与退出**：单方缩短工期、随时解除、自动续期、拒绝续约、没收已付款、限制退出协助。
7. **文件与解释**：单方更新网页/政策/附件、最终解释权、未提供上游文件自动并入、一般项目沟通改变主合同。
8. **权利处分**：单方转让、分包、变更控制人、许可宣传、使用名称商标、保留或删除数据。

对每项单方权利提出机制性审查问题：

- 是否有客观触发条件和适用范围，而非纯粹任意？
- 是否需要事先通知、对方确认、证明或独立记录？
- 我方是否有异议、修复、价格/工期调整、替代履行或退出权？
- 后果是否与影响相称，是否形成格式条款或免责效力问题？
- 是否与授权、变更、违约、解除和争议条款协调？

## 三、商业锁定与退出成本

法律上有效的条款仍可能让我方被不利交易长期锁定。按交易检查：

- 最低采购/最低消费、独家或排他、最惠待遇、竞业/不招揽、自动续期和续约价格；
- 预付款、不可退费用、长期质保金、提前解约费、未摊销成本、预期利润和沉没成本；
- 数据不可导出、格式封闭、源代码/源文件缺失、账号密钥受控、第三方接口限制；
- 背景 IP 或许可范围使成果无法替换供应商，迁移协助和过渡服务缺失；
- 关键人员、唯一供应来源、不可替代分包方、履约担保和保险不足；
- 多合同交叉违约、交叉抵扣、交叉解除导致局部问题扩散为整个合同族风险。

评价时写清锁定期间、退出触发、可量化成本、替代方案和证据，不把“长期合作”本身当风险，也不把任何排他安排当然认定为无效。

## 四、商业不利、法律不利、执行不利分开

- **法律不利**：可能无效、不成为合同内容、可撤销、不得对抗、违法监管或救济受限；按法律核验程序表达。
- **商业不利**：现金流、价格、工作量、锁定期限、资源占用、责任敞口或谈判地位不利；无须伪装成违法。
- **执行不利**：约定看似有利，但标准、授权、证据、通知、期限或第三方配合使其难以实际使用。

同一 finding 可兼具多类，但分别写依据和解决方式。用户接受商业不利时记录其决定，不把接受表述为法律风险或执行风险已经消失。

## 五、要价清单与谈判梯度

在用户需要谈判方案时，先将保护需求分层。诊断阶段只写机制、优先级和 Q-ID，不输出可粘贴成稿，也不自行填商业数值；确认后的条款阶段才形成首选文本和具体变量。层级如下：

| 层级 | 含义 | 输出要求 |
|---|---|---|
| 法律底线 | 不可通过让步排除的强制要求 | 明确依据，不提供违法“备选” |
| Must-have | 缺了会使核心交易目的、重大责任或退出机制不可接受 | 与 S1/S2 finding 和用户红线对应 |
| Should-have | 显著改善现金流、证据、履约和责任分配 | 诊断阶段给机制；确认后给首选文本及可谈变量 |
| Nice-to-have | 操作便利和体例优化 | 不作为无关紧要的签约阻断理由 |

### 让步与交换

让步应保留最低保护，不用无条件退让换“合作态度”。可围绕同一风险交换机制，例如：

- 接受更短验收期，以完整提交、客观测试、提醒程序和隐蔽瑕疵例外为条件；
- 接受合理责任上限，以核心例外、保险/担保、第三方索赔程序和长期数据义务为条件；
- 接受分期付款安排，以明确里程碑、无争议金额先付、逾期暂停权和担保为条件；
- 接受一定排他或最低量，以期限、区域/客户范围、最低对价、绩效条件和退出权为边界。

这些只是谈判分析路径，不是自动建议用户交换。任何价款、税率、比例、责任、期限或范围变化都须用户确认；法律底线不可交换。

### 商业论证

谈判建议尽量说明对方为何也能接受：减少验收管理成本、降低争议和举证不确定性、让价格与真实工作匹配、提高供应连续性、明确双方合规责任。避免只给“对我方更有利”而无法谈判的结论。

## 六、输出前反向检查

1. 每条建议确实保护我方在当前角色下的目标，不是从另一角色模板复制。
2. 首选、退让和最低保护分开；未把 Nice-to-have 夸成签约红线。
3. 任何交换都保留法律底线、核心救济和必要证据。
4. 未擅自改变已确认交易实质，未用“完善”名义夹带价格或责任重分配。
5. 用户决定、未接受建议和残余风险均可追溯。
