# XQY 快速审核 v1

这是 hetong 系列可按甲乙方立场切换的快审子技能。**快在报告简明、重点固定，不减免全文阅读、数字复算和关键法源核验。**
只影响本流程，不替换普通深度审核；固定条款引用同级craft的唯一真源，不复制一套条款正文。

## 调用与边界

- 用户点名本技能，或明确说“xqy快审／徐启源口径快审”时采用；“快速看一下”本身不触发本专用口径。
- 继承 [hetong-craft](../hetong-craft/SKILL.md) 的原件只读、保密与授权纪律；本页是其审核模式的专用分支，**先按本页受理，不再加载通用大报告模板或强制弹类别问卷**。
- 提示词可简写：“xqy快审，站甲方／乙方，合同在……”。按用户指定的合同一方并核对其实际买方／卖方角色；常规甲方采购使用甲方M/A条款，乙方销售使用乙方B条款。合同角色反转时按真实交易角色选库，在报告写清，不能因甲乙方名称而套错义务。未指定且无冲突时沿用原采购方口径；已明确乙方时不再要求确认或转回甲方。
- 默认交付**两份Word**：①详细审核报告，负责依据、分析及直接可读的文字修订建议；②原稿批注稿，负责注意事项／需修订位置的简短提醒，并指向报告同一R编号。保留Markdown及映射、核验记录，原件只读。
- 调用本技能包含“详细报告＋仅加批注副本”的已定输出范围，不重复询问是否生成第二份。报告中的替换／新增／删除建议不代表已获同意；批注稿保留原正文、原样式和既有修订批注，不自动执行这些建议或生成红线。用户本轮明确只要报告等例外时从其指令。
- 不重问已有明确的对象、立场和输出。调用本快审口径包含**按本方固定条款进行相关性只读匹配并重点论述**：已有本次类别选择／排除时遵守；未另限类别时扫描本方目录，仅按八项及明显重大问题读取相关正文，不弹全套问卷、不伪造类别提交。该授权不等于全选写入、接受库中参数或修改原件。

## 本方固定条款重点

先按 [立场与固定条款匹配](references/stance-and-fixed-clauses.md) 读取本方当前索引及命中模块的完整实质要求；不能仅凭关键词或标题认定符合。
在第1—8项或框架外问题的**对应位置**增加加粗引导的短段：“甲方／乙方固定条款重点〔编号；符合情况〕”，说明本方要求、合同差异和本次处理意见。已充分满足也可简短表述“已符合，保留”；缺失、冲突、部分符合或待核实则重点解释，不额外堆一张全库清单。
库内参数只是本次审阅比较基准。提示词已给出的参数和排除事项优先；有差异同时说明，不能擅改成库内数值，更不能将其写成双方已确认条件。固定条款命中不自动产生批注：有实际修订、实质待核实或具体履约注意时才建立R事项。

## 两份交付和统一编号

按 [双文件与编号衔接](references/paired-delivery.md)执行。八项大纲顺序不变；在相应项内用`R-001`等稳定编号列详细事项，正文直接展示建议替换／新增／删除的文字。编号不等于M/A/B固定条款编号、RL段落定位或Word内部批注ID。
批注采用“R编号＋建议修订／履约注意／待核实＋一两句说明＋详见《本版审核报告》对应R编号”；不得只写编号和“见报告”而没有内容。纯提醒明确“正文保留”，不得误写成“已修订”。同一事项多处锚点共用R编号，同段多事项可合并一条原生批注并分别列R编号。
只输出**两份业务交付物**，技术计划和映射放`核验/`。批注作者沿用本次明确署名，无指定用“合同审阅”，不借XQY名称冒充个人。

## 固定汇报顺序

正文直接从以下第1项开始，前面只放标题和一行日期／立场；不加执行摘要、目录或大段免责声明。

1. **基本情况**：产品简称（尽量四字，如“超微3T”，以事实准确优先）、数量、价格、交付时间。正文与文件名、附件冲突必须显著指出；附一句签前判断。
2. **发票**：开票触发、多久开、类型／税率及本方责任或救济边界；采购方关注逾期罚则，销售方同时核对B10等固定要求。
3. **履约保函**：核对银行白名单、线上核验、覆盖／生效／减额／失效及付款衔接；采购方关注10日未开出的退出目标，销售方按B07/B09/B11等审阅，不直接套采购方解除条件。
4. **产品配套资料**：区分前置与随货资料；按实际标的检查SN、PO、PI、物流、原厂权益及对应关系。
5. **验收**：A外包装和设备外观；B性能基准测试／压测及官方最新规范，测试版本、环境、标准和结果留证；防止签收替代性能验收。
6. **违约**：不交货、转售罚则及责任范围是否明确；联查退款、解除、总责任上限及免责，按本方立场评价，已存在的保护不误报为缺失。
7. **不可抗力**：按本方基线明确应删除、收窄或保留的具体文字；不把普通供应链风险自动等同不可抗力，也不一概删除销售方适用的B05特别安排。
8. **廉洁条款**：有无、是否完整，必要时给简短样例。

随后仅列**框架外明显经济及法律问题**，每项“位置＋问题／影响＋解决方案或建议写法”。无额外重大问题则不凑数。
末尾合并一小段核验依据、范围限制和待确认参数。正文不塞完整风险台账、长法条或重复总结。

八项标题和顺序固定，保护方向按立场变化。第2—7项中的增加罚则、付款前保函、删除免责等原采购方方向不能无条件用于乙方；见 [审阅重点](references/review-focus.md) 与本方固定条款。所有要求是**审核比较目标**，不是银行产品保证、法定标准或双方已定条件。

用户要求时间轴，或跨项付款、交付、保函及开票关系难以看清时，使用craft的[合同履约时间轴规范](../hetong-craft/references/contract-timeline.md)。放在相关项或报告分析附件，保留八项顺序和本报告字体；不因图中每个节点重复建R事项或批注，不把完整表插入原合同。

## 执行

1. 锁定指定原件，记录路径和SHA256，另存只读基线；缺少文件不以类似文件替换。
2. 阅读正文、表格、附件和图片。旧`.doc`先另存转换件并独立提取交叉核对；含修订／批注的DOCX先用 [word_reader.py](../hetong-craft/scripts/word_reader.py) 核对原文、接受、标记、时间线和批注，不接受／拒绝原件历史。
3. 先确定本方及实际交易角色，还原数量、价税、交期、付款／开证链，再按八项检查并匹配本方固定条款；另扫责任上限、质保、主体、管辖等明显重大问题。保留模块编号、原文定位、正文来源和符合情况，不将文件名、图片描述或大写残留金额当成交事实。
4. 关键法律结论按 [法律核验](../hetong-review/references/legal-verification.md) 查当前官方全文；对外仅检索抽象问题。商业风险、待补事实与效力结论分开。
5. 每项先简述现状，再以R事项承担详细分析。需要修改的，报告中直接写建议条文或明确删除文字与新增位置，不只说“建议完善”；具体参数不明仍占位。已满足且无履约提醒的不强行建R；具体注意事项可建注意类R并在批注中提醒。
6. 未确认金额、期限、违约比例、保额、起算点等在样例写`【待确认：具体参数】`。用户本次明确给出的参数不擅自改掉；原文提取和复算数字注明来源。需要用户确定重要商业条件时，以普通文字集中提问并等待，不用选择卡、超时或默认值确认；不妨碍先交付待确认版报告。
7. 按 [Word交付规格](references/report-format.md) 填结构化数据，先运行craft红线工具`inspect`取得RL定位，再填精确锚文本。用 [双交付生成器](scripts/build_bundle.py) 的`--dry-run`核对全部映射，成功后生成完整的两份交付；它复用craft原生批注引擎，只允许comment操作，**不代替合同审核或语义选区判断**。
8. 运行双向核验：每条新增批注均有报告详细项、每个应批R均有锚点；逐一核对文档版本、文件名及R编号。源指纹、正文/样式/历史保留检查通过，再渲染和查看报告与批注稿版面；原生批注另作结构核验，无头预览看不到批注不算丢失。只报告实际验证，不声称Word/WPS实机兼容已测。

## 快捷命令

`PY`使用当前宿主已验证的Office Python（Codex先调用workspace dependencies工具；其他宿主沿用hetong Office隔离环境），不要新装一套依赖。

```bash
"$PY" <本技能>/scripts/build_bundle.py --input 产出/快审数据.json --out-dir 产出/交付_v1 --dry-run
"$PY" <本技能>/scripts/build_bundle.py --input 产出/快审数据.json --out-dir 产出/交付_v1
"$PY" <本技能>/scripts/build_bundle.py --verify 产出/交付_v1
python3 <hetong-craft>/scripts/office_kit.py render 产出/交付_v1/*.docx --out 产出/核验/预览
```

基础格式示例见 [虚构快审数据](assets/example-report.json)，双交付字段见 [双文件规则](references/paired-delivery.md)。旧`build_report.py`保留用于明确只要报告的任务及兼容旧输入，不代替默认双交付。示例只演示格式，**禁止把其合同事实、金额、法源或结论移植到真实报告**。
