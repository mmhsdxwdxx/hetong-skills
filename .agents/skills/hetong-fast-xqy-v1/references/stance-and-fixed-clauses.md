# 立场判断与本方固定条款重点

## 先定立场和比较范围

1. 提示词“站甲方／乙方”确定我方是哪一合同主体；再读正文确认其实际是买方还是卖方。常规甲方＝采购方、乙方＝销售方时分别用buyer、seller库；角色反转则按实际角色选库，并注明“甲方（卖方，按销售方固定条款审阅）”等，不能混用两套目标。
2. 真源只有craft：[甲方派生索引](../../hetong-craft/references/buyer-clause-catalog.json)、[乙方派生索引](../../hetong-craft/references/seller-clause-catalog.json)。索引给模块、类别、来源编号和`file`；按其路径读取当前分类Markdown中命中模块的“实质要求”和必要范例，记录实际版本。甲方以M编号为主并保留A来源；乙方用B编号。
3. 本快审调用已获用户授权做本方固定条款的相关性只读比对。已有本次类别选择、明确不用或排除事项时遵守；未单列类别时遍历本方目录发现相关项，只读取相关正文。不要把未选／不相关类别写成默认整改任务，不新增共管等未要求的交易架构。
4. 与八项及明显经济法律问题无关的条款不因存在于库中而展开。另一方条款可以帮助判断对方诉求，但不能标成本方固定条款。固定条款不能代替现行法律核验。

## 报告怎么写

每项相关论述后用一段，正文仍为宋体，仅引导标签加粗：

> **甲方固定条款重点〔M03／A03、A09；部分符合〕：** 本方固定要求是保函连续覆盖未结清预付款并安排展期或退款；本合同只写到期日，未约定到期前的处理机制。应补足该机制；具体期间如与本次指令不同，列明差异后待确认，不擅自替换。

> **乙方固定条款重点〔B07；冲突〕：** 本方固定条款对开函期限及不可归责迟延设有保护；本合同要求更短期限且到期即可解除，偏离我方基线。应重点协商期限和解除条件，保留依法可行的免责范围；不直接改成甲方的快速解约方案。

- “符合”：解释保留的本方核心保护，一句即可，不为显示审阅而新增批注。
- “部分符合／缺失／冲突”：写核心要求＋对应原文或缺口＋对本方的影响／处置，不只列编号，也不整段复制库文。
- “待核实”：标明缺少的事实／附件，不能把尚未核验写成不符合。
- 用户本次明确改变或排除某固定要求：以本次指令优先，必要时标“本次明确偏离”，不再要求恢复旧基线。
- 多个模块命中同一问题时合并论述并列编号，避免重复放大风险。是否符合由语义判断，编号校验和关键词匹配均不能替代。

## 与Word生成器衔接

输入增加`stance: {party: "甲方"|"乙方"|"我方", role: "buyer"|"seller", categories?: [...]}`。
`categories`缺省表示按本方库查找相关项；显式空数组表示本次不用本方固定条款。已有选择填实际类别，不填工具猜测。

在`basics`、任一`sections`或`extras`对象添加：

```json
"fixed_clauses": [
  {"id": "M03", "status": "部分符合", "analysis": "本方固定要求……；本合同……；建议……。"}
]
```

`status`仅用“符合、部分符合、缺失、冲突、待核实、本次明确偏离”。`analysis`须是已核正文后的简明论述。
生成器从本方当前索引补齐来源编号，拒绝跨方编号、未知编号或超出显式类别范围的标记；它不负责语义匹配，不证明已读正文或商业条件已确认。
