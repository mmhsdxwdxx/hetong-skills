# 审阅输出规则（v2.0.2）

本规则由 hetong-craft、hetong-review、hetong-fast-xqy-v1 与 hetong-word 共用。适用于本轮新写的意见和修订，不追改历史审阅；本次用户明确的“只读、只批注、不改正文”等限制仍优先。

## 1. 批注只处理真实问题

甲乙方固定视角条款是核对依据，不是批注清单。先核对全文、附件、例外及等效安排；仅命中固定条款、措辞不同但效果相同、已经充分解决的问题，不加批注。允许零条批注。

保留的批注必须对应具体错误、实质风险、必要修订或影响履行的待核实事项。不能只写“符合固定条款”“建议保留”“有风险，请注意”。履约提醒只有确有具体行动或证据要求时才保留。

## 2. 批注短而完整

通常一句，必要时两句，直接说清“问题本质＋处理”。只保留理解该问题必需的事实、影响或理由，不重复原文，不粘贴完整替换条款、长法条、推演过程或报告段落。不能为了短而只剩“有问题”“已修改”。

- `R-001｜开票期限缺少起算点，付款后无法确定何时逾期。`
- `R-002｜英文金额与中文不符，已按中文更正。`
- `R-003｜“甲放”为笔误，已改为“甲方”。`

以上仅示范表达，不能成为新合同参数。双交付生成器的单项 `comment_summary` 上限为120字符，防止把详细论证塞进批注；这不是目标篇幅，仍应优先压成最短的完整句子。

## 3. 禁止文件指向，双交付使用同号

批注、回复及会写入批注的修订理由不得出现“详见XXXX”“参见报告”等文件指向，也不得出现另一份审阅文件的名称、路径、链接、页码或内部存储位置。每条意见脱离详细报告仍能看懂。

“批注 Word＋另一份详细意见”模式中，每个独立问题使用稳定编号 `R-001、R-002……`，Word批注和详细意见显示同号。编号仅用于对应，不是文件指引：允许 `R-001｜缺少起算点，已补齐。`，禁止 `R-001，详见报告。`。单独批注稿不强制加号。

一个问题涉及多处锚点时复用同号，详细意见只保留一个事项；一条物理批注含多个独立问题时逐项显示各自编号。不得用相同编号代表不同问题，也不得有无对应项的编号。M/A/B条款库编号、RL段落号、Q决策号、Word内部数字ID及文件索引不替代对外问题编号。历史事项沿用原号，新事项续号。

## 4. 明确错误直接批注并修订

一般审核、修订和快审任务未明确禁止改文时，对以下可客观确认、修复方向明确的错误，直接在副本中做最小必要修订并加简短批注，不为每处错误再次请示：错别字、漏多字、病句和不通顺表达；明显违反逻辑、法律常识、经济常识或基本人文常识的表述；明显违背已经核实的适用规范、会计或法务通常做法的表述。

直接修订必须能说明确定的错误及依据，不能把谈判偏好、库中示范、个人文风或存在多种合理选择的惯例当作错误。涉及法律或会计规范时先核验适用依据；缺少事实、需要选择新方案、或者需要确定付款主体、金额、期限、担保等商业条件时，只说明具体问题，待用户以普通文字确认。用户已明确的商业实质不因“常识纠错”被替换。

保留原件和历史修订；已签合同也只生成拟变更副本，不声称已改变生效条款。正常受理记录应写明“明确错误最小纠正”的范围并沿用本规则的既有授权，不伪造用户提交。用户本次明确只读或只批注时不写正文。

## 5. 中英对照以中文为审稿基准

逐条核对中文与英文的主体、义务、金额币种、数量、否定词、期限起点、条件、例外和责任。原有中英文不一致时，按中文直接批注并修订英文；中文本轮有改动时，同步调整对应英文，不保留旧英文或遗漏新增、删除内容。

中文自身有明确错误的，先按第4项修正中文，再据此修订英文；中文有歧义或未定商业条件的，不自行选一种含义翻译。语言效力条款另有约定时，同时提示该冲突并按本次中文审稿基准处理拟稿，不把本次修订口径说成已生效合同的法律结论。交付前成对核验最终接受视图。

## 6. 简要审核报告最多两页

用户指明或流程要求“简要/简短审核报告”时，采用简单结构：总体判断；关键问题及处理；确需确认的事项。直接讲清问题、影响和动作，删去过程叙述、重复原文、全库覆盖表、长法条及无关背景。无问题时直接说明核对范围和结果，不凑页数。

总篇幅含标题、正文、表格、说明及附页不得超过2页；不得靠极小字号、过窄边距、隐藏文字或转为附录规避。详细意见和简要报告是不同交付物，不把所有深度报告都强制压成两页，也不把“快审”自动等同于“简报”。

交付前按实际排版核对页数。使用 LibreOffice 渲染时运行 `scripts/verify_brief_report.py` 核对渲染清单、源文件指纹与PDF实际页数；使用WPS等其他路径时记录实际页数。超过两页先删重、合并同根因问题并重排；核心问题仍须说透，不以截断或漏掉重大问题达标。
